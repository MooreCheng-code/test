# 企業破產預警互動式儀表板 (Bankruptcy Risk Dashboard)

本專案提供基於多模型集成（Ensemble E_A）的企業財務破產風險評估與假設分析互動式介面。

---

## 1. 專案簡介與用途

本系統建立於嚴格無洩漏的機器學習流程與凍結模型之上，整合不同演算法模型之百分位排名，提供破產風險預警、特徵敏感度分析與財務指標對照。

> [!IMPORTANT]
> **本儀表板僅供機器學習工程、模型可解釋性與作品集展示教學之用，不得作為任何實際商業借貸、授信核貸、投資決策或企業信用評等之依據。**

## 3. 如何啟動 App

> [!CAUTION]
> **執行目錄要求**：App 與其底層凍結模型相依於專案內部模組（如 `src.preprocessing` 與 `src.scoring`）。**啟動時工作目錄必須為專案根目錄 `bankruptcy/`**，以確保 Python 模組能被正確解析與反序列化。

### 啟動步驟

1. **進入專案目錄**：
   ```bash
   cd bankruptcy
   ```

2. **建立並啟用乾淨虛擬環境**（支援 Python 3.10 至 3.14）：
   ```bash
   python -m venv .venv
   # Windows PowerShell:
   .venv\Scripts\Activate.ps1
   # Linux / macOS:
   source .venv/bin/activate
   ```

3. **安裝相依套件**：
   ```bash
   pip install -r requirements-app.txt
   ```

4. **啟動 Streamlit 服務**：
   ```bash
   streamlit run app/app.py
   ```

5. **瀏覽應用程式**：
   啟動後，瀏覽器連線至 `http://localhost:8501` 即可開始操作。預設設定檔已鎖定本機位址，不對公開網路開門。

## 4. 四大功能分頁說明

- **分頁 1【風險總覽與預警】**：
  - 輸入 18 項最具代表性的財務比率（分為前 8 項主要輸入與 10 項進階輸入）。
  - 提供「典型非破產公司（健全體質）」與「典型破產公司（高風險體質）」一鍵載入功能。
  - 即時輸出 E_A 風險百分位（0% ~ 100%）、校準後估計破產機率，以及四種嚴格程度的工作點燈號（綠色安全 / 紅色預警）。
  - 自動列出推高風險與降低風險的前三大財務因子歸因。
- **分頁 2【財務體質診斷與假設分析】**：
  - 診斷表：比對使用者輸入值在訓練母體分布中的百分位位置，針對跨數量級偏態特徵自動提示尺度警告。
  - What-if 曲線：動態調整任一財務指標，即時呈現全模型重新推論之風險評分變化軌跡，支援依分布分位數（Percentile）或等距數值（Value）取樣。
- **分頁 3【模型原理與工作點成本】**：
  - 解說三模型（ExtraTrees、LightGBM、XGBoost）之特徵側重與等分位校準融合架構。
  - 呈現不同目標召回率（Recall 80%、90%、95%、100%）對應的決策門檻、預警比例（Alert Ratio）與精準度成本。
- **分頁 4【限制、偏誤與免責聲明】**：
  - 詳列模型適用邊界、外推風險與常見認知偏誤。
  - 說明未納入模型的重大非財務資訊（例如經理人操守、產業景氣反轉、重大合約變更等）。
  - 完整載明免責條款。

## 5. 核心操作概念

### 5.1 分位數集成 (Percentile Ensemble, E_A)
不同的機器學習模型（隨機森林變體與梯度提升樹）輸出的原始機率或評分尺度各異。系統透過各模型在交叉驗證訓練折上的累積經驗分布函數（CDF），將預測值映射為 0 至 1 的百分位數後再取均值。此設計能保留各模型之排序能力，同時消除演算法間評分尺度的系統性偏差。

### 5.2 門檻與安全邊界 (Thresholds & Margin)
系統不採用單一預設的 0.5 切分點，而是依據模型在嚴格交叉驗證折中達到指定目標召回率（如捕捉 90% 潛在違約事件）所需的最低門檻。介面中同時計算當前評分與各門檻之間的差距（Margin），呈現風險緩衝空間。

### 5.3 18 個核心輸入與中位數補值
模型底層包含特徵選擇與前處理轉換，需輸入完整的欄位結構：
- 使用者透過介面填寫最重要的 18 項財務比率。
- 其餘 54 個模型實際使用之特徵與 23 個未入模欄位，均由系統自動以嚴格無洩漏之訓練資料中位數（`defaults.json`）自動補齊，兼顧操作便捷度與推論嚴謹性。

## 6. 限制與免責聲明

本應用程式遵循嚴謹之機器學習工程規範，但使用者應充分理解以下關鍵限制：

1. **資料集依據**：本模型訓練基於一份去識別化之財務比率資料集，原始欄位精確會計定義與資料授權狀況尚待進一步確認。
2. **母體分布與環境漂移**：校準機率係以訓練母體之先驗分布為基礎。若真實商業環境發生系統性變遷（如法規大幅更迭或總體經濟危機），機率估計可能產生偏差。
3. **相關性非因果關係**：特徵歸因與假設分析僅反映模型在特定特徵擾動下的數值預測變化，不代表改善該指標即可必然降低真實違約機率。
4. **模型詳細效能報告**：所有交叉驗證指標、測試折表現、門檻對照表與實驗日誌，請參閱專案正式報告 [RESULTS_SUMMARY.md](RESULTS_SUMMARY.md)。本介面內文不寫死任何評估數據。

## 7. 專案目錄結構（App 相關）

與互動介面直接相依的檔案清單如下：

```
bankruptcy/
├── app/
│   ├── app.py                     # Streamlit 介面進入點與 UI 渲染
│   ├── logic.py                   # 純推論邏輯、特徵建構、歸因與分析運算（無 Streamlit 依賴）
│   ├── ui_text.py                 # 介面文字、章節說明、免責宣告與定義
│   └── assets/
│       ├── defaults.json          # 訓練集統計量、分位數網格、補值中位數與預設輪廓
│       └── feature_notes.json     # 18 項輸入特徵之財務意義與指標說明
├── scripts/
│   └── make_app_defaults.py       # 產生 defaults.json 之離線批次腳本（僅使用訓練折資料）
├── tests/
│   ├── test_app_defaults.py       # 驗證 defaults.json 結構與分位數網格
│   ├── test_app_logic.py          # 單元測試 logic.py 運算邏輯
│   ├── test_app_smoke.py          # 端到端冒煙測試（驗證全介面函式與元件輸出）
│   └── test_frozen_hashes.py      # 比對 outputs/logs/e6_preflight.txt 驗證凍結檔案 SHA256 雜湊
├── .streamlit/
│   └── config.toml                # 伺服器綁定 localhost 與停用數據收集設定
├── requirements-app.txt           # App 執行與模型推論所需之精確套件版本清單
└── README_APP.md                  # 本說明文件
```

## 8. 公開到 GitHub 之前要確認之檢核清單

在將本專案代碼推送到公開 GitHub 儲存庫之前，請務必完成以下審核清單：

- [ ] **資料來源與授權確認**：確認原始資料集（如 `data.csv`）之授權是否允許開源釋出。若不可公開，應在 `.gitignore` 中排除原始資料，並保留以 `defaults.json` 驅動的 App 獨立推論功能。
- [ ] **模型檔案大小與託管**：檢查 `outputs/models/final/` 下之模型檔大小。目前所有檔案總計約 25.2 MB，最大檔案 `model_M3.joblib` 約 21.3 MB，均低於 GitHub 100 MB 限制；若未來重新訓練產生超過 50 MB 之模型檔，建議使用 Git LFS 或託管於 GitHub Releases。
- [ ] **暫存命名檔案清理說明**：`outputs/models/final/_tmp_oof_*.npy` 檔名雖含 `_tmp_`，但因部分回歸測試與雜湊校驗對其存在依賴，屬於歷史命名遺留，詳情請參考 [docs/KNOWN_ISSUES.md](../docs/KNOWN_ISSUES.md)。
- [ ] **本機路徑與機密檢視**：確認所有程式與文件內無寫死本機絕對路徑（如 `C:\Users\...`）、內部金鑰或伺服器認證資訊。
- [ ] **忽略設定生效**：確認 `.streamlit/secrets.toml`、`__pycache__/`、`*.pyc` 與備份資料夾均已被 `.gitignore` 排除且未被 Git 追蹤。
