### Stacking 元學習器正則化候選
- 登錄表 ID：ENS_STACKING_C_CANDIDATES
- 白話意義：堆疊法（Stacking）使用羅吉斯迴歸作為裁判，決定給各成員模型多少權重。`c_candidates` 是裁判模型正則化強度的候選清單 `[0.01, 0.1, 1.0]`。

<!-- /registry -->
- 證據等級：【本專案實測：對照實驗】（E3 各集成架構實測）
- 調大／調小會怎樣：
  - 調大 C（例如 1.0）：【一般經驗，未經本專案驗證】（lab_03，已完成：見 labs/README.md）正則化弱，裁判更容易針對內層 OOF 分數做微調權重，但容易在元特徵層次發生輕度過擬合。
  - 調小 C（例如 0.01）：【一般經驗，未經本專案驗證】（lab_03，已完成：見 labs/README.md）正則化極強，裁判傾向給予各模型均等權重，逼近等權平均。
- 風險與陷阱：在 E3 實測中，Stacking 的 AR@0.95 並未顯著超越等權平均（Equal Weighted Average），且等權平均不需要額外擬合元學習器，具備最高簡約性與魯棒性。
- 如何安全實驗：在 `bankruptcy/src/ensemble.py:284` 的 `fit_stacking_meta_learner` 中修改候選清單進行 CV 測試（lab_03，已完成：見 labs/README.md）。
- 已知限制或矛盾：專案最終固化採用等權平均法（Equal Weights），未採用 Stacking。
