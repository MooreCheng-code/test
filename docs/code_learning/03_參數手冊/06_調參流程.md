### 三點損失評估目標召回率 TUNE_LOSS_RECALLS
- 登錄表 ID：TUNE_LOSS_RECALLS
- 白話意義：調參目標函數所關注的三個核心召回率關卡 `[0.8, 0.9, 0.95]`。演算法不是看單一閾值，而是計算在 80%、90%、95% 三個召回率下的平均 log 預警比率，要求模型全面兼顧。

- 證據等級：【專案設定（未做對照）】
- 調大／調小會怎樣：
  - 加入 1.0（100% 召回）：【一般經驗，未經本專案驗證】（規劃中：lab_04）要求抓出全部破產，此時預警比率暴增至極端值，會強烈主導並扭曲整體的調參損失。
  - 僅看 0.95 單點：【一般經驗，未經本專案驗證】（規劃中：lab_04）可能導致模型過度擬合單一分位點，在其他工作點（如 0.90）效能劣化。
- 風險與陷阱：三點損失取對數平均 $\frac{1}{3} \sum \log(\text{AR}@R_k)$，具有幾何平均抑制作弊的效果，防止單點作弊。
- 如何安全實驗：呼叫 `bankruptcy/src/tune.py:82` 的 `compute_three_point_log_loss` 進行自訂評估（規劃中：lab_04）。
- 已知限制或矛盾：三點目標設定為商業破產預警之常用工作區間（專案未記載選擇理由）。
