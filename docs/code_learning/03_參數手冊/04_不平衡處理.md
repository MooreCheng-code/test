# 04 不平衡處理參數手冊

本文件彙整「資料不平衡處理」核心參數。本專案破產資料極度不平衡（破產正樣本僅佔約 3.2%）。專案在 E1a 實測了 S0～S6 等多種策略，並在 E2 調參中將不平衡策略列為超參數聯合最佳化。

- 調大／調小會怎樣：
  - 選擇 S0（不重抽樣）：【本專案實測：對照實驗】（E1a `bankruptcy/outputs/e1a_imbalance_experiment.csv`）在 E1a 實測中，簡約原則選定 S0 為基準，對多數模型（M1、M3、M4）不抽樣能維持最佳泛化能力，避免合成噪聲。

- 如何安全實驗：在 `bankruptcy/src/tune.py:132` 修改 Optuna 候選清單，或於 `bankruptcy/src/pipelines.py:214` 指定 `imbalance` 參數（規劃中：lab_03）。
- 已知限制或矛盾：歷史文件中曾有「放棄 SMOTE」的過時宣稱，但事實上 M2 與 M5 的最佳參數與部署模型均包含 S3（SMOTE 0.3）（參見 `docs/code_learning/_facts_verified.md` 第 5 項）。

- 證據等級：【本專案實測：對照實驗】（E1a 實驗完整評估）
- 調大／調小會怎樣：
  - 增加 `sampling_strategy`（例如 S4 的 0.5）：【本專案實測：對照實驗】（E1a `bankruptcy/outputs/e1a_imbalance_experiment.csv`）破產樣本合成比例拉高，召回率可能提升，但精確率與 PR-AUC 通常會因合成噪聲而顯著下降。
  - 降低 `sampling_strategy`（例如 S2 的 0.1）：【本專案實測：對照實驗】（E1a `bankruptcy/outputs/e1a_imbalance_experiment.csv`）合成比例溫和，對分佈破壞較小，但對某些樹模型的召回增益不明顯。
- 風險與陷阱：`k_neighbors` 預設為 5，若少數族群樣本極少（例如小於 5），SMOTE 會拋出異常。
- 如何安全實驗：呼叫 `bankruptcy/src/pipelines.py:112` 的 `_get_resampler`，只在訓練折內部執行（規劃中：lab_03）。
- 已知限制或矛盾：專案在 E1a 實測了 S0～S6，但在 E2 調參時因計算預算考量，僅將 S0 與 S3 納入 Optuna 候選空間（專案未記載選擇理由）。
