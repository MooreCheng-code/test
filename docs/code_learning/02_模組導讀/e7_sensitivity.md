# 模組導讀：E7 敏感度與穩定性分析 (`prevalence_sensitivity.py`、`seed_stability.py`)

## 1. 模組定位與設計初衷

機器學習模型在實驗室的測試集取得優異成績，並不代表模型能夠在真實世界中穩健運作。在金融風控實務中，模型經常面臨兩大嚴峻挑戰：

1. **母體盛行率變動（Prevalence Shift，E7a）**：
   - 實驗室的訓練集通常具備特定的正樣本比例（本專案訓練集為 3.23%）。然而在真實經濟環境中，企業破產率會隨著景氣循環大幅波動（例如在繁榮期可能降至 0.5%～1.0%，在衰退期可能攀升至 5.0%）。
   - 當破產率下降時，模型如果繼續使用固定的機率門檻，會發生什麼事？精確率會跌到多少？調查人員的負擔會增加幾倍？這就是 **E7a 盛行率敏感度分析**（`bankruptcy/src/prevalence_sensitivity.py`）要回答的問題。
2. **隨機種子穩定性（Random Seed Stability，E7b）**：
   - 現代集成演算法（如 ExtraTrees、XGBoost、LightGBM）與重採樣技術包含大量隨機過程（隨機特徵採樣、隨機種子初始化等）。
   - 我們看到的優異表現，究竟是演算法的真實泛化能力，還是剛好碰上了「運氣好」的特定隨機種子？
   - **E7b 隨機種子穩定性分析**（`bankruptcy/src/seed_stability.py`）透過更換 5 組截然不同的隨機種子，量化演算法內部的隨機擾動程度。

## 2. E7a：母體盛行率敏感度分析 (`prevalence_sensitivity.py`)

### 2.1 貝氏調整公式與分析原理

當模型由訓練環境遷移到不同盛行率 $\pi \in (0, 1)$ 的真實母體時，假設各類別條件特徵分佈 $P(x \mid y=1)$ 與 $P(x \mid y=0)$ 保持不變（即條件不變性假定，Covariate Invariance，一般經驗，未經本專案驗證），模型的真陽性率（TPR）與偽陽性率（FPR）將維持固定。

基於此假定，各項營運指標可透過貝氏定理推導（`bankruptcy/src/prevalence_sensitivity.py:7-13`）：

$$
\text{預警比例 (Alert Proportion)} = \pi \cdot \text{TPR} + (1 - \pi) \cdot \text{FPR}
$$

$$
\text{精確率 (Precision)} = \frac{\pi \cdot \text{TPR}}{\pi \cdot \text{TPR} + (1 - \pi) \cdot \text{FPR}} = \frac{\pi \cdot \text{TPR}}{\text{Alert Proportion}}
$$

$$
\text{每捕獲一家所需調查數 (Effort per Positive)} = \frac{1}{\text{Precision}}
$$

$$
\text{每萬家企業預期預警數} = 10,000 \times \text{Alert Proportion}
$$

$$
\text{每萬家企業預期捕獲破產數} = 10,000 \times \pi \times \text{TPR}
$$

### 2.2 純 Python 玩具範例：盛行率劇變對調查負擔的衝擊

> [!NOTE]
> **【玩具數字範例，非專案正式 E7a 完整報告數字】**
> 以下提供一段獨立的純 Python 模擬腳本（不呼叫任何專案專有函式），僅以單組固定參數示範當母體破產率由 3.2% 驟降至 1.0% 及 0.5% 時，調查負擔如何成倍大幅上升之計算原理。專案正式的完整多工作點分析請見 2.3 節。

```python
# 純 Python 示範：貝氏敏感度推算（獨立玩具範例）
def calculate_operational_impact(tpr: float, fpr: float, prevalences: list[float]):
    print(f"固定效能參數: TPR = {tpr*100:.1f}%, FPR = {fpr*100:.1f}%\n" + "-" * 65)
    print(f"{'盛行率 (pi)':<12}{'預警比例':<12}{'精確率 (Precision)':<18}{'每抓 1 家需查幾家 (Effort)'}")
    print("-" * 65)

    for pi in prevalences:
        alert_prop = pi * tpr + (1.0 - pi) * fpr
        precision = (pi * tpr) / alert_prop
        effort = 1.0 / precision

        print(f"{pi*100:>5.1f}%      {alert_prop*100:>6.2f}%      {precision*100:>10.2f}%         {effort:>10.2f} 家")

# 以本專案 E_A 在 R80 運作點之點估計值 (TPR=82.55%, FPR=9.57%) 為例之玩具示範
calculate_operational_impact(
    tpr=0.825450,
    fpr=0.095725,
    prevalences=[0.050, 0.032, 0.020, 0.010, 0.005]
)
```

**玩具範例輸出結果與商業意義解讀（直觀展示）**：
- **景氣衰退期（$\pi = 5.0\%$）**：精確率高達 **31.2%**，調查人員每查 **3.2 家** 就能抓到 1 家破產企業。
- **基準環境（$\pi = 3.2\%$，本專案訓練集）**：精確率為 **22.2%**，每查 **4.5 家** 能抓到 1 家破產企業。
- **經濟擴張期（$\pi = 1.0\%$）**：精確率驟降至 **8.0%**，每查 **12.5 家** 才能抓到 1 家破產企業（調查負擔擴大近 3 倍）。
- **極度繁榮期（$\pi = 0.5\%$）**：精確率暴跌至 **4.2%**，調查人員必須連續審查 **24.1 家** 預警企業才能找到 1 家真正的破產案例，95% 以上的調查工作均為偽陽性白工！

> [!TIP]
> **商業啟示（一般經驗，未經本專案驗證）**：
> 當外部總體經濟好轉、違約率顯著下降時，風控主管應主動調高預警門檻（收緊預警名單），否則第一線稽核團隊將會被海量的偽陽性淹沒，造成營運資源的嚴重浪費。

## 3. E7b：隨機種子穩定性分析 (`seed_stability.py`)

### 3.1 實驗設計與評估協定

為了確認集成模型 $E_A$ 是否對演算法內部的隨機擾動敏感，`seed_stability.py` 設計了嚴格的對照實驗（`bankruptcy/src/seed_stability.py:43-130`）：
1. **固定切分**：維持相同的 15 個外層折（5 折 $\times$ 3 次重複），排除資料切分差異。
2. **改變隨機種子**：測試 5 組跨度極大的隨機種子：`SEEDS = [42, 7, 123, 2025, 31337]`。
3. **模型重構**：對每組種子，使用 E2b 固化超參數重新建立 M3（ExtraTrees）、M4（XGBoost）、M5（LightGBM）管線（將種子傳入模型與重採樣模組），並在各驗證折上計算 $E_A$（百分位數平均）之三點對數損失（3-point log loss）、AR@0.95 與 PR-AUC。

### 3.3 核心發現：「種子標準差 $\ll$ 折間標準差」的統計學意義

這組實驗揭示了極為重要的機器學習方法論啟發：

1. **演算法隨機性極小（Algorithm Robustness）**：
   - 跨 5 組種子的 PR-AUC 標準差僅為 **0.0017**（極差僅 0.0042，0.4743～0.4785）；AR@0.95 標準差僅為 **0.148 倍**。
   - 這支持判定 $E_A$ 模型本身的架構極為穩健，並沒有因為隨機種子不同而產生結果大起大落的現象。
2. **種子間標準差遠小於折間標準誤（Seed Std $\ll$ Fold SE）**：
   - PR-AUC 的種子間標準差（0.0017）僅為折間標準差（0.0791）的 **2.1%**，甚至只有折間標準誤（0.0204）的 **8.3%**。
   - AR@0.95 的種子標準差（0.148 倍）也僅為折間標準誤（0.550 倍）的 **26.9%**。
3. **重要結論與警惕**：
   - **演算法隨機性小，不代表資料抽樣不確定性小！**
   - 很多初學者在調參時發現換個種子分數變動不大，就誤以為「模型的不確定性很小」；但本實驗清楚支持判定，**最大的變異來源是資料抽樣的變異（Fold Std 達 2.13 倍）**，而非演算法內部隨機種子的變異（Seed Std 僅 0.15 倍）。
   - 在評估模型時，**重複交叉驗證（5 折 $\times$ 3 次重複）所捕捉到的樣本分佈擾動，比單純換種子跑多次重要得多**。
