### 2.1 原始資料欄名首尾空白引發 `KeyError`
- **症狀**：
  在讀取資料或特徵篩選時，以標準財務指標名稱查詢（例如 `df['Net value growth rate']`）拋出 `KeyError: 'Net value growth rate'`。
- **原因**：
  台灣經濟新報（TEJ）原始 CSV 檔頭字串中包含非預期的首尾半形空格（例如 `' Net value growth rate'`）。若直接以去除空格的標準欄名索引，將導致找不到欄位。
- **排查步驟（安全唯讀）**：
  執行以下指令檢視前 5 個含有首尾空格的原始欄名：
  ```bash
  python -c "import pandas as pd; df = pd.read_csv('bankruptcy/data/data.csv', nrows=1); spaces = [c for c in df.columns if c != c.strip()]; print('空格欄名數量:', len(spaces)); print('範例:', spaces[:5])"
  ```
- **預防措施**：
  在資料讀取入口統一執行標準化清理。專案於 `data_audit.py:49`、`cv.py:205` 與 `score_new_data.py:90` 在讀入資料後立即執行 `df.columns = df.columns.str.strip()`。
- **來源出處**：
  `bankruptcy/src/data_audit.py:49`、`bankruptcy/src/cv.py:205`、`bankruptcy/score_new_data.py:90`、Git Commit `bbf2376`。

### 2.2 預測分數離散與粗階梯引發預警爆增（同分悲觀決勝陷阱）
- **症狀**：
  設定目標召回率為 90% 或 95%，模型發出的預警家數突然暴增至接近全體樣本（預警倍數 $AR \approx N/P \approx 31\text{x}$），但 ROC-AUC 帳面數字並未完全歸零。
- **原因**：
  模型輸出的預測分數分佈過於離散（例如單決策樹葉節點過少、或使用未校準且大量輸出 0.0/1.0 的分類器）。專案遵循嚴格的業務防護採用**悲觀同分規則**（`score >= thr`，負樣本優先佔用預警名額）。當門檻剛好切在大量平手的葉節點分數上時，為達到目標召回率，所有同分樣本被迫全數納入預警名單，造成預警總量爆炸。
- **排查步驟（安全唯讀）**：
  檢測預測分數的唯一值數量（Unique Scores），觀察是否存在粗階梯現象：
  ```bash
  python -c "import numpy as np; scores = np.load('bankruptcy/outputs/models/final/reference_M3.npy'); print('M3 唯一分數個數:', len(np.unique(scores))); print('最小/最大分數:', scores.min(), scores.max())"
  ```
- **預防措施**：
  1. 風控系統應優先採用隨機森林、ExtraTrees 或 Boosting 等多樹集成模型，透過數百棵樹的分數平均形成連續平滑的分佈。
  2. 深入理解召回率受限於 $\lceil R \times P \rceil$ 整數階梯，切勿採用樂觀判定（`>`）來掩飾同分缺陷（見 Bug 06 示範）。
- **來源出處**：
  `PROJECT_STATE.md:58`、`bankruptcy/src/metrics.py:110-138`、`bankruptcy/src/thresholding.py:105, 720`、`labs/lab_01_tree_depth.py`、Git Commit `a8ce317`。

### 2.3 M5 調參 CV 與最終凍結模型 `subsample_freq` 參數不一致 (F-02)
- **症狀**：
  在比對外層交叉驗證（E2a/E3）紀錄與最終部署模型時，發現 M5（LightGBM）在 CV 時含有動態特徵抽樣 `subsample_freq=1`，而固化參數檔 `best_params/M5.json` 與部署模型 `model_M5.joblib` 卻為 `subsample_freq=0`（停用 bagging）。
- **原因**：
  在 `tune.py:169` 中，Optuna 搜尋空間動態採樣了 `subsample_freq=1`；但在最佳參數序列化（`tune.py:930`）時，僅保存了 `best_trial.params` 字典，條件參數 `subsample_freq` 未被完整寫入 JSON，導致固化模型回退至 LightGBM 預設值 `0`。
- **排查步驟（安全唯讀）**：
  檢視固化參數與已記錄之差異：
  ```bash
  python -c "import json; d = json.load(open('bankruptcy/outputs/models/best_params/M5.json')); print('M5 固化參數 subsample_freq:', d.get('subsample_freq', 0))"
  ```
- **預防措施**：
  1. 專案在 `PROJECT_STATE.md:117` 與 `_findings.md`（F-02）正式記錄此差異：CV 指標僅供選模參考，最終模型效能以 E6 盲測集表現為準。
  2. 在 `lab_03` 擴充對照實驗（45 組配對，成對差異均值 +0.0035，95% CI 跨 0，小於種子雜訊 0.0182），客觀確認在該樣本下未檢出差異，但嚴謹宣告該結論不得外推至 E6。
- **來源出處**：
  `PROJECT_STATE.md:117`、`docs/code_learning/_findings.md:31-61` (F-02)、`bankruptcy/src/tune.py:169`。

### 2.4 重跑 `freeze_final_components()` 拋出 `UnboundLocalError` (F-01)
- **症狀**：
  在已存在固化產物的環境中，嘗試再次呼叫 `thresholding.py` 之 `freeze_final_components()` 時，拋出 `UnboundLocalError: cannot access local variable 'final_references' where it is not associated with a value`。
- **原因**：
  在 `bankruptcy/src/thresholding.py:631-636` 中，若硬碟上已存在 `reference_{m}.npy` 等快取檔案，快取載入邏輯會執行 `final_references[m] = np.load(ref_file)` 並 `continue`。然而變數 `final_references = {}` 卻在下方第 672 行才被宣告初始化，導致快取命中分支提早存取未綁定之區域變數。
- **排查步驟（安全唯讀）**：
  檢視 `thresholding.py` 第 630～675 行的程式碼結構：
  ```bash
  python -c "import ast; tree = ast.parse(open('bankruptcy/src/thresholding.py', encoding='utf-8').read()); print('thresholding.py 語法解析正常')"
  ```
- **預防措施**：
  推論與服務端應一律使用 `load_final_components()` 進行唯讀載入；`freeze_final_components()` 為一次性固化函式，且正式部署時不可在原目錄直接重跑破壞雜湊。
- **來源出處**：

### 2.5 SHAP 值加總性檢驗失敗 (SHAP Additivity Check Failure)
- **症狀**：
  在執行可解釋性分析或單元測試時，`shap.TreeExplainer` 拋出 `AssertionError: Additivity check failed in TreeExplainer`，或特徵 SHAP 值總和加期望值不等於模型輸出。
- **原因**：
  梯度提升樹（如 XGBoost 與 LightGBM）若在二元分類下直接以機率空間（Probability）或對數勝算空間（Log-odds / Margin）混合計算，或 `link` 參數設定不當，會導致加總公式失效。在非線性 Sigmoid 轉換後，機率不具備嚴格線性可加性。
- **排查步驟（安全唯讀）**：
  執行解釋模組專屬單元測試：
  ```bash
  python -m pytest bankruptcy/tests/test_explain.py bankruptcy/tests/test_local_explain.py
  ```
- **預防措施**：
  在 `explain.py:100-140` 與 `scoring.py:180-210` 中，TreeExplainer 一律以模型的未轉換輸出空間（Margin / Log-odds）計算 SHAP，再使用 `scipy.special.logit` 或 `decision_function` 進行邊界校驗，並允許合理數值浮點容差（$10^{-4}$）。
- **來源出處**：
  Git Commit `3654b80`、`f465509`、`bbf2376`、`bankruptcy/tests/test_local_explain.py`。

### 2.6 Optuna SQLite 與 Joblib 快取殘留導致結果無法更新
- **症狀**：
  修改了模型搜尋空間或特徵處理邏輯後重新執行調參腳本，但輸出日誌顯示「直接載入既有 Trial」或評估結果完全不變；或因陣列維度不符拋出 `ValueError`。
- **原因**：
  `tune.py` 與 `ensemble.py` 具備續跑機制，會依據固定 study 名稱讀取本機 SQLite 資料庫（`optuna_study.db`）或 `outputs/models/cache/*.joblib`。若未變更實驗識別碼，系統會認定既有 Trial 已完成而略過計算。
- **排查步驟（安全唯讀）**：
  檢視快取目錄現存檔案清單與大小（不刪除）：
  ```bash
  python -c "from pathlib import Path; p = Path('bankruptcy/outputs/models/cache'); files = list(p.glob('*.joblib')) if p.exists() else []; print('快取檔案數量:', len(files))"
  ```

- **預防措施**：
  在進行新實驗或變更超參數空間時，應給予獨立的 `--study-name` 或在獨立的沙盒目錄執行，避免與舊快取衝突。**嚴禁隨意手動刪除生產產物目錄**。
- **來源出處**：
  `docs/KNOWN_ISSUES.md:27`、`docs/code_learning/_findings.md:67-83` (F-04)、`bankruptcy/src/tune.py:610`。

### 2.7 隨機種子未全域錨定引發評估指標漂移
- **症狀**：
  相同程式碼在不同電腦或不同執行次數下，PR-AUC 或 AR@0.95 產生波動（PR-AUC 漂移量級約 0.0385，見 Bug 07 量測）。
- **原因**：
  機器學習管線中包含多個隨機模組：SMOTE 合成抽樣、QuantileTransformer 次取樣、RandomForest 特徵隨機抽樣、LightGBM 行抽樣等。若有任一組件未設定 `random_state`，系統將使用系統隨機種子，導致各次執行結果無法嚴格對齊。
- **排查步驟（安全唯讀）**：
  檢查專案全域隨機種子設定：
  ```bash
  python -c "import bankruptcy.config as c; print('專案全域 SEED:', c.SEED)"
  ```
- **預防措施**：
  專案在 `config.py:27` 定義全域常數 `SEED = 42`，並強制要求所有模型、切分器（`StratifiedKFold`）與轉換器（`QuantileScaler`、`SMOTE`）建構時均顯式傳入 `random_state=config.SEED`。
- **來源出處**：
  `PROJECT_STATE.md:52`、`bankruptcy/config.py:27`、`labs/bugs/bug_07_missing_random_state.py`、`06_解答.md:Bug 07`。

### 2.10 小樣本下 `QuantileTransformer` 之 `n_quantiles` 警告 (F-03)
- **症狀**：
  在小樣本切分（如 100 筆合成資料或極小外層驗證折）上擬合 `QuantileTransformer` 時，終端機出現 `UserWarning: n_quantiles is greater than the total number of samples`。
- **原因**：
  scikit-learn 的 `QuantileTransformer` 預設 `n_quantiles=1000`。若樣本總筆數少於 1,000，分位數數量大於樣本數，系統會發出警告並自動降階。
- **排查步驟（安全唯讀）**：
  執行合成測試觀察 scikit-learn 行為：
  ```bash
  python -c "from sklearn.preprocessing import QuantileTransformer; import numpy as np; qt = QuantileTransformer(n_quantiles=1000); qt.fit(np.random.randn(200, 2))"
  ```
- **預防措施**：
  專案在 `bankruptcy/src/preprocessing.py:310` 之 `QuantileScaler.fit()` 中採用動態防護：`self.n_quantiles_ = min(1000, len(X))`，從根源消除此警告。
- **來源出處**：
  `docs/code_learning/_findings.md:62-66` (F-03)、`bankruptcy/src/preprocessing.py:310`。

### 2.11 初學者常見的特徵工程與評估洩漏錯誤
- **症狀**：
  離線驗證集或交叉驗證指標表現優異（如 PR-AUC 高達 0.95+），但在盲測集或實際推論時表現斷崖式崩跌。
- **原因**：
  在機器學習實作中不慎引入各種類型的資料洩漏（Data Leakage）。常見形態包含：
  1. **切分前執行有監督特徵篩選**（見 `bug_01`）：在交叉驗證切分前使用全體標籤挑選特徵，PR-AUC 平均虛增 +0.1305。
  2. **切分前執行 SMOTE 過抽樣**（見 `bug_02`）：在切分前對全集生成合成少數類，造成合成樣本跨折滲透，PR-AUC 虛增 +0.3009。
  3. **測試集盛行率逆向滲透**（見 `bug_08`）：推論時依賴動態讀取測試集的破產盛行率來調整門檻，抹煞市場真實漂移。
  4. **跨折分數直接全域池化**（見 `bug_10`）：忽視各折分數尺度的系統性偏移，直接 pooling 計算全域指標，PR-AUC 產生 +0.0412 偏差。
- **排查步驟（安全唯讀）**：
  至 `labs/bugs/` 目錄執行沙盒示範腳本，檢視各項錯誤之量化影響：
  ```bash
  python labs/bugs/bug_01_preprocessing_leakage.py
  python labs/bugs/bug_02_resampling_leakage.py
  python labs/bugs/bug_10_uncalibrated_score_pooling.py
  ```
- **預防措施**：
  1. 一律將前處理與採樣封裝於 `imblearn.pipeline.Pipeline` 中，確保所有 fit 操作僅在外層訓練折進行。
  2. 詳讀 [06_練習題.md](06_練習題.md) 與 [06_解答.md](06_解答.md) 之 20 次重複量測數據，建立工程免疫力。
- **來源出處**：
  `labs/bugs/bug_01` 至 `bug_10`、`docs/code_learning/06_練習題.md`、`docs/code_learning/06_解答.md`。
